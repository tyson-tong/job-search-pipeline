From searches to site inputs

Each site filters differently, so a search is translated to what each site can do. Filters applied on the site cost nothing for excluded jobs; filters applied after import only exclude a job whose value is known, and store it with status filtered and a reason.

LinkedIn's AI search dropped its salary, job-type, workplace, and sort filters; the Indeed actor never had them. The tracker's Searches tab previews every run and notes each widened window or skipped option.

How duplicates are found

Every scraped record is normalised, then checked in order. The first match wins; no match creates a new job.

Same site copy

This site's ID (e.g. seek:81234567) is already in job_sources, or, for a posting without an ID, the same URL without tracking parameters.

Exact content

Same fingerprint: a hash of company, title, location, and description. Catches exact reposts.

Same job on another site

Same employer (ignoring "Pty Ltd" etc.) and title, same city when both name one, first seen in the last 90 days, and descriptions sharing at least half their words.

Safety net: possible duplicates (never merged)

The merge is strict, so a recruiter re-post under another name, a reworded title, or a suburb can stay separate. jobflow web and tailor-cv compare against jobs from the last 180 days, ignoring employer and place (titles ≥ 60% alike, ads ≥ 40% alike), and warn if one is already applied, interviewing, offered, or accepted.

A merged job keeps the first site's details (and the longest description). Because status, notes, and scores belong to the job, marking it applied covers every site it was listed on:

Created by migrations/001–006; jobflow migrate applies any not yet listed in schema_migrations.

applications

Your progress on a job.

  • job_id → jobs
  • status, notes dated
  • applied_at, follow_up_on, updated_at

Every status change.

  • job_id → jobs
  • from_status, to_status
  • via, changed_at

workflow_runs

Log of match, tailor, interview-prep.

  • job_id → jobs, kind, status
  • model_name, started_at, finished_at

Statuses: new (the Inbox), interested, not interested, applied, interviewing, offered, accepted, declined, rejected, withdrawn, filtered. Not interested, accepted, declined, rejected, withdrawn, and filtered are closed: hidden from the tracker's default view and never scored. Filtered is only set by imports.

CV work

Matching

  • LLM lists requirements: required or preferred; matched, partial, or not evidenced; with CV quotes.
  • Each quote is checked against the CV file; unverifiable ones downgrade the item.
  • Score = matched 1, partial 0.5, averaged per group, weighted by required_weight / preferred_weight.
  • Reused until the CV file changes.

Tailoring

  • Uses the best-matching CV unless --cv is given.
  • Only the cv section goes to the LLM; design and settings are kept.
  • Errors (render skipped): changed contact details, new or altered employers, positions, dates, education; removed entries; new numbers.
  • Warnings: new tool or skill names. Written to REVIEW_REQUIRED.md.

Interview prep

  • Tavily web search for company facts and news.
  • Four agents in parallel: company, role, CV evidence, likely questions.
  • An editor agent merges them into one briefing with sources.
  • The invitation email is optional and never stored.

Keeping Apify cost down

Ask for less

  • posted_within_days = 1 for daily runs.
  • max_results per run.
  • max_cost_usd hard cap per run.
  • Only the sites you list are called.

Filter on the site

  • Seek applies salary, job type, arrangement, and classification before charging.
  • LinkedIn skips company-page scraping.

Still paid for

  • Jobs you already have (actors can't skip them).
  • The same job on several sites, or matched by two terms.
  • Extra results from a widened date window.

Each run's actual cost is stored in scraper_runs.cost_usd.
