From searches to site inputs

Each site filters differently, so a search is translated to what each site can do. Filters applied on the site cost nothing for excluded jobs; filters applied after import only exclude a job whose value is known, and store it with status filtered and a reason.

LinkedIn's AI search dropped its salary, job-type, workplace, and sort filters; the Indeed actor never had them. The tracker's Searches tab previews every run and notes each widened window or skipped option.

How duplicates are found

Every scraped record is normalised, then checked in order. The first match wins; no match creates a new job.

Same site copy

This site's ID (e.g. seek:81234567) is already in job_sources, or, for a posting without an ID, the same URL without tracking parameters.

Exact content

Same fingerprint: a hash of company, title, location, and description. Catches exact reposts.

Same job on another site

Same employer (ignoring "Pty Ltd" etc.) and title, same city when both name one, first seen in the last 90 days, and descriptions sharing at least half their words.

Same ad, same title

Identical title (ignoring case and punctuation), same country, first seen in the last 90 days, and ads at least 95% the same words (30+ words), under any employer spelling or city.

Safety net: similar jobs (never merged)

The merge is strict, so a recruiter re-post with an edited ad, a reworded title, or a suburb can stay separate. jobflow web compares against jobs from the last 180 days in the same country, ignoring employer and city (titles ≥ 60% alike, ads ≥ 40% alike), and warn if one is already applied, interviewing, offered, or accepted. Labelled highly similar when ads are ≥ 80% alike, else similar. The same ad in another country is shown alongside, not as similar.

A merged job keeps the first site's details (and the longest description). Because status, notes, and scores belong to the job, marking it applied covers every site it was listed on:

jobs id 42 source linkedin "Data Analyst" Acme Pty Ltd job_sources linkedin:4012345678 → 42 https://au.linkedin.com/jobs/view/4012345678 seek:81234567 → 42 https://www.seek.com.au/job/81234567 job_observations 42 × run 118 (LinkedIn), 42 × run 119 (Seek) original records applications 42 applied 2026-09-25: Applied via referral

workflow_runs

Log of match, tailor, cover-letter, interview-prep; the last three skip jobs already logged, except a draft that failed the fact check (NEEDS-FIX), which is drafted again unless you fixed it by hand (FIXED-BY-HAND). A logged job whose output was deleted (its YAML draft, cover-letter.docx, or interview-prep.html) is done again.

  • job_id → jobs, kind, status
  • model_name, error, started_at, finished_at

Statuses: new (the Inbox), interested, not interested, applied, interviewing, offered, accepted, declined, rejected, withdrawn, filtered, archived. My jobs shows interested, applied, interviewing, offered, and accepted by default; not interested, filtered, and archived jobs never appear there. Only interested jobs are scored. Filtered is set by imports and jobflow update-searches; the tracker's Filtered tab moves a job back to the Inbox. Archived is set by jobflow ingest and jobflow web on filtered jobs more than 2 weeks past their posted date; they stay in the database and still match as duplicates, but are never shown.

CV work

Matching

  • LLM lists requirements: required or preferred; matched, partial, or not evidenced; with CV quotes.
  • Each quote is checked against the CV file; unverifiable ones downgrade the item.
  • Score = matched 1, partial 0.5, averaged per group, weighted by required_weight / preferred_weight.
  • Only Interested jobs, against the 1 or 2 CVs cvs names; each is scored once and never again, even if a CV changes.

Tailoring

  • Runs for every Interested job without a draft; jobs already done are skipped, unless their YAML draft was deleted. A draft that failed the fact check is drafted again, unless you've edited it. --format docx or latex for a job already done writes that file from its re-checked draft, with no LLM call.
  • Uses each job's best-matching CV unless --cv is given (an unscored job is scored first).
  • A hiring-manager reviewer revises the draft; the revision is kept only if it has no more fact-check errors than the first draft.
  • Only the cv section goes to the LLM; design and settings are kept.
  • Errors (render skipped): a changed, added, or removed header field (the headline is checked like section text), new or altered employers, positions, dates, education; an entry whose employer, position, dates, and education details don't match one original entry together (a date or title moved between entries); a removed employer, role, or education entry; new numbers. A draft with errors leaves no older PDF, .docx, or .tex beside it.
  • Always the YAML draft and RenderCV's PDF of it (no PDF if the fact check found errors); --format docx or latex adds a .docx or a .tex.
  • A PDF over 1 page (or --max-pages N): the fewest of the least relevant bullets that make it fit are cut, found by re-rendering in a binary search (never an entry's last bullet).
  • Warnings: new tool or skill names, and a page left mostly empty by an entry moved whole to the next page. Written to CV_REVIEW.md.
  • Optional cover letter (jobflow cover-letter): reviewed the same way; numbers not in the CV, job ad, or research are errors; new terms and placeholders are warnings.

Interview prep

  • Tavily web search for company facts and news.
  • Four agents in parallel: company, role, CV evidence, likely questions.
  • An editor agent merges them into one briefing with sources.
  • Runs for every Interviewing job without a briefing; jobs already done are skipped.

Keeping Apify cost down

Ask for less

  • posted_within_days = 1 for daily runs.
  • max_results per run.
  • max_cost_usd hard cap per run.
  • Only the sites you list are called.

Filter on the site

  • Seek applies job type, arrangement, and Seek classifications before charging. Salary bounds are applied after import so salaryless postings are retained.
  • LinkedIn skips company-page scraping.

Still paid for

  • Jobs you already have (actors can't skip them).
  • The same job on several sites, or matched by two terms.
  • Extra results from a widened date window.

Each run's actual cost is stored in scraper_runs.cost_usd.
